# AI 评测与可观测性

> Demo 能跑不代表 Production 可用。AI 系统必须能回答：为什么这次成功、为什么这次失败、修改以后到底有没有变好。

## 两条主线

```text
Evaluation
+
Observability
```

## Evaluation

需要建立 Dataset，而不是每次靠人工“感觉不错”。

### 常见评测对象

#### LLM
- correctness
- relevance
- style
- safety
- structured output validity

#### RAG
- retrieval recall
- context precision
- faithfulness
- answer relevance

#### Agent
- tool selection
- tool argument correctness
- task completion
- unnecessary tool calls
- trajectory quality

## Ragas
- 官网：https://docs.ragas.io/
- GitHub：https://github.com/explodinggradients/ragas
- Metrics：https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/

值得关注：
- Context Precision
- Context Recall
- Faithfulness
- Response Relevancy
- Tool Call Accuracy
- Agent Goal Accuracy

## Observability

一次 Agent Run 至少应该能看到：

```text
Request
↓
Prompt / Context
↓
Model Call
↓
Tool Call
↓
Tool Result
↓
Model Call
↓
Final Answer
```

同时记录：
- latency
- token usage
- errors
- retries
- cost
- model
- tool name
- trace id

## OpenTelemetry
- 官网：https://opentelemetry.io/
- Python：https://opentelemetry.io/docs/languages/python/
- GitHub：https://github.com/open-telemetry/opentelemetry-python

这是值得长期掌握的通用 Observability 标准，不局限于 AI。

## LangSmith
- Docs：https://docs.langchain.com/langsmith/

适合 Agent / LLM tracing、datasets、evaluation 和 debugging。

## Golden Dataset

为关键场景维护一批固定样本：

```text
Input
Expected Behavior
Expected Tool
Expected Facts
Expected Constraints
```

每次改：
- prompt
- model
- retrieval
- tool
- agent workflow

都跑 regression。

## 我的结论

AI 应用进入生产以后，最重要的能力之一不是“再加一个模型”，而是：

可观测 → 可评测 → 可复现 → 可改进。
