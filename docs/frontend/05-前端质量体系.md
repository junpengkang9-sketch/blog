# 前端质量体系

> 质量不是一份“代码规范”，而是一套从开发到上线持续拦截问题的系统。

## 分层

### Static
- TypeScript
- ESLint
- Prettier

### Unit / Component
- Vitest
- Testing Library

### E2E
- Playwright

### Commit Gate
- Husky
- lint-staged

### CI
- GitHub Actions

## Vitest
- 官网：https://vitest.dev/
- Guide：https://vitest.dev/guide/
- GitHub：https://github.com/vitest-dev/vitest

适合 Vite 生态中的 Unit Test。重点掌握 test、expect、mock、fixture、coverage。

## Testing Library
- 官网：https://testing-library.com/
- Guiding Principles：https://testing-library.com/docs/guiding-principles/
- GitHub：https://github.com/testing-library

最值得保留的思想：测试应尽量接近用户真正使用软件的方式。

少测试内部实现，多测试：
- 用户看到了什么
- 用户能做什么
- 操作后系统产生了什么结果

## Playwright
- 官网：https://playwright.dev/
- GitHub：https://github.com/microsoft/playwright

用于浏览器级 E2E。重点能力：多浏览器、自动等待、Trace、Screenshot、Network、并行测试。

## 推荐质量链路

开发阶段：TypeScript + ESLint

格式阶段：Prettier

提交阶段：Husky + lint-staged

单元测试：Vitest + Testing Library

E2E：Playwright

合并阶段：GitHub Actions 跑 lint + test + build

## 测试金字塔不要机械执行

真正需要的是按风险分配测试：

- 纯函数、工具类 → Unit
- 组件行为 → Component
- 登录、支付、核心业务链路 → E2E
- 第三方 API / 数据库 → Integration

## 我的结论

好的质量体系不是“规则最多”，而是能以最低成本尽早发现最昂贵的问题。
