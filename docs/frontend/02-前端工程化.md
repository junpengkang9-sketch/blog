# 前端工程化

> 目标：把“一个现代前端项目到底由哪些工程系统组成”讲清楚。

## 工程地图

前端工程化可以拆成：

- Runtime：Node.js
- Package：pnpm
- Language：TypeScript
- Build：Vite / Rspack
- Quality：ESLint / Prettier
- Test：Vitest / Testing Library / Playwright
- Git：Husky / lint-staged / Conventional Commits
- CI/CD：GitHub Actions

## Node.js
- 官网：https://nodejs.org/
- GitHub：https://github.com/nodejs/node

它是现代前端工具链的运行时基础。需要理解版本管理、ESM/CJS、process、环境变量、文件系统与脚本执行。

## pnpm
- 官网：https://pnpm.io/
- GitHub：https://github.com/pnpm/pnpm

价值：依赖安装快、磁盘利用率高、严格依赖关系，并天然适合 workspace / Monorepo。

## TypeScript
- 官网：https://www.typescriptlang.org/
- Handbook：https://www.typescriptlang.org/docs/handbook/
- GitHub：https://github.com/microsoft/TypeScript

核心价值不是“给 JavaScript 加几个类型”，而是在大型代码库中把接口、约束和重构风险提前到开发阶段发现。

## ESLint
- 官网：https://eslint.org/
- GitHub：https://github.com/eslint/eslint

解决：静态分析、规则约束、常见错误检测。重点理解 Flat Config、规则层级、插件和自动修复。

## Prettier
- 官网：https://prettier.io/
- Why Prettier：https://prettier.io/docs/why-prettier
- GitHub：https://github.com/prettier/prettier

核心价值：把“格式讨论”交给工具，让团队把注意力放在代码设计而不是空格和换行。

## Git 工程

### Husky
- 官网：https://typicode.github.io/husky/
- GitHub：https://github.com/typicode/husky

### lint-staged
- GitHub：https://github.com/lint-staged/lint-staged

### Conventional Commits
- 官网：https://www.conventionalcommits.org/

推荐组合：commit 前只检查变更文件；CI 再做完整 lint、test、build。

## CI/CD：GitHub Actions
- 官网：https://docs.github.com/actions
- 核心介绍：https://docs.github.com/en/actions/get-started/understand-github-actions

理解模型：

Event → Workflow → Job → Step → Action / Command

## 建议的默认技术栈

新项目可优先从下面这套开始：

Node.js + pnpm + TypeScript + Vite + ESLint + Prettier + Vitest + Playwright + GitHub Actions

不要为了“工程化”一次装几十个插件。每引入一个工具，都应该能回答它具体降低了哪类成本或风险。
