# 微前端（Micro Frontends）

> 更新时间：2026-09-19  
> 目标：理解微前端解决什么问题、主流方案如何取舍，而不是只会调用框架 API。

## 核心判断

微前端真正解决的通常不是“代码太多”，而是：

- 多个团队并行开发
- 多个业务域相互独立
- 不同模块需要独立发布
- 老系统需要渐进迁移
- 一个前端单体已经成为组织协作瓶颈

如果只是一个团队、一个产品、一个发布节奏，优先做好模块化和 Monorepo，通常比上微前端更划算。

## 必读资料

### Micro Frontends
- 官网：https://micro-frontends.org/
- GitHub 示例：https://github.com/neuland/micro-frontends
- 推荐：★★★★★

值得看：从组织边界、业务边界、独立交付讲微前端，而不是从框架 API 开始。

### Martin Fowler：Micro Frontends
- 原文：https://martinfowler.com/articles/micro-frontends.html
- 推荐：★★★★★

核心观点：微前端最大的价值是团队自治、渐进升级和独立交付，同时也会引入依赖重复、体验一致性、通信和运维复杂度。

## 主流方案

### single-spa
- 官网：https://single-spa.js.org/
- GitHub：https://github.com/single-spa/single-spa

适合用来理解最底层的应用编排思路：

URL / 状态变化 → 判断激活应用 → load → bootstrap → mount → unmount

重点看：Applications、Parcels、Root Config、Routing、Import Maps。

### qiankun
- 官网：https://qiankun.umijs.org/
- GitHub：https://github.com/umijs/qiankun

特点：建立在 single-spa 思路之上，补充 HTML Entry、JS 沙箱、样式隔离、预加载等工程能力。适合国内 Vue / React 中后台和存量系统改造。

### Wujie
- 官网：https://wujie-micro.github.io/doc/
- GitHub：https://github.com/Tencent/wujie

特点：Web Components 作为容器，iframe 提供运行环境隔离。值得研究隔离、保活、通信、路由同步和预加载设计。

### Module Federation
- 官网：https://module-federation.io/
- Webpack 官方：https://webpack.js.org/concepts/module-federation/
- GitHub：https://github.com/module-federation/core
- Vite 插件：https://github.com/module-federation/vite

一句话：让多个独立构建、独立部署的应用在运行时暴露和消费模块。

核心概念：Host、Remote、exposes、remotes、shared、singleton、runtime loading。

## 选型思路

| 场景 | 优先研究 |
|---|---|
| 小团队 / 单产品 | 模块化单体、Monorepo |
| 多团队大型中后台 | qiankun / Wujie / single-spa |
| 存量系统渐进迁移 | single-spa / qiankun / Wujie |
| 多应用运行时共享模块 | Module Federation |

## 真正需要回答的问题

1. 应用边界按什么划分？
2. 谁负责顶层路由？
3. 登录态如何共享？
4. 跨应用状态是否真的需要共享？
5. CSS 如何隔离？
6. React / Vue 等运行时依赖是否共享？
7. 子应用故障是否会拖垮主应用？
8. 发布和回滚能否真正独立？
9. 公共组件升级如何控制影响面？
10. 日志、监控、报错如何定位到具体子应用？

## 我的结论

当组织边界、发布边界和业务边界已经明显分离，而代码仍被迫绑在同一个前端单体里时，微前端才开始真正有价值。
