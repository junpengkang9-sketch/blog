# 前端构建工具

> 更新时间：2026-09-19  
> 目标：理解构建工具背后的共同模型，而不是只会写配置文件。

## 先掌握这些概念

- Entry / Output
- Dependency Graph
- Module Resolution
- Transform
- Bundle
- Chunk
- Tree Shaking
- Code Splitting
- HMR
- Plugin
- Source Map

理解这些之后，Webpack、Vite、Rspack、Rolldown 才不再是互不相关的 API。

## Vite
- 官网：https://vite.dev/
- Why Vite：https://vite.dev/guide/why
- GitHub：https://github.com/vitejs/vite

### 当前重点
Vite 8 已使用 Rolldown 作为统一的 Rust bundler，开发与生产构建工具链进一步统一。

重点理解：Dev Server、HMR、依赖处理、插件机制、生产构建、Environment API。

## Rolldown
- 官网：https://rolldown.rs/
- Introduction：https://rolldown.rs/guide/introduction
- GitHub：https://github.com/rolldown/rolldown

定位：Rust 编写、面向现代 JavaScript 工具链的 bundler，与 Vite 深度协作。

值得关注：Rollup 兼容思路、Oxc 工具链、性能、插件生态迁移。

## Rspack
- 官网：https://rspack.rs/
- Introduction：https://rspack.rs/guide/start/introduction
- GitHub：https://github.com/web-infra-dev/rspack

定位：Rust 高性能 Web bundler，强调现代化 webpack API 和 webpack 生态兼容。

适合重点研究：大型项目、Webpack 迁移、构建性能、Loader / Plugin 兼容。

## Webpack
- 官网：https://webpack.js.org/
- Concepts：https://webpack.js.org/concepts/
- GitHub：https://github.com/webpack/webpack

虽然新项目未必首选，但它定义和普及了很多构建概念。理解 Entry、Loader、Plugin、Chunk、Code Splitting 仍然很有价值。

## esbuild
- 官网：https://esbuild.github.io/
- GitHub：https://github.com/evanw/esbuild

Go 编写的高性能构建工具。非常适合理解“原生语言重写工具链”带来的数量级性能提升。

## SWC
- 官网：https://swc.rs/
- GitHub：https://github.com/swc-project/swc

Rust 编写的编译平台，重点价值在 parsing、transform 和代码生成。

## 怎么选

| 场景 | 建议 |
|---|---|
| 新的常规 Vue / React 项目 | Vite |
| 现有大型 Webpack 项目性能瓶颈 | Rspack / Rsbuild |
| 研究 Vite 新底层 | Rolldown |
| 理解传统构建体系 | Webpack |
| 单独做超快 transform | esbuild / SWC |

## 我的结论

不要把“换构建工具”当成工程升级本身。先测量冷启动、HMR、生产构建和 CI 时间，再针对真正的瓶颈选方案。
