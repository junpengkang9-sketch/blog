# Python 测试与代码质量

## 推荐基础栈

```text
pytest
+
Ruff
+
Type Hints
+
pyproject.toml
```

## pytest
- 官网：https://docs.pytest.org/
- Getting Started：https://docs.pytest.org/en/stable/getting-started.html
- GitHub：https://github.com/pytest-dev/pytest

重点掌握：
- test discovery
- assert
- fixture
- parametrize
- monkeypatch
- mock
- integration test

## Ruff
- 官网：https://docs.astral.sh/ruff/
- GitHub：https://github.com/astral-sh/ruff

Ruff 可以承担：
- lint
- format
- import sorting
- 自动修复
- 大量 Flake8 规则替代

## Type Checking

### mypy
- 官网：https://mypy-lang.org/
- GitHub：https://github.com/python/mypy

### Pyright
- GitHub：https://github.com/microsoft/pyright

不用追求“100% 类型覆盖”，优先覆盖：
- public API
- service boundary
- database model
- tool schema
- external data

## 推荐测试分层

### Unit
纯函数、解析、业务规则。

### Integration
数据库、API、Tool、第三方服务。

### E2E
完整 Agent / API 流程。

## Agent 项目特别要测什么

- Tool 参数生成是否正确
- Tool 返回异常怎么处理
- Timeout / Retry
- Structured Output 是否满足 Schema
- RAG 返回为空
- 多 Tool 并发
- LLM provider 异常

## 我的结论

代码质量工具应该是“自动拦截器”，不是人工检查清单。

开发时 Ruff，测试用 pytest，边界加 Type Hints，CI 再做完整验证。
