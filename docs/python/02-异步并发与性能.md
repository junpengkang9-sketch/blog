# Python 异步、并发与性能

> 对 AI / Agent 应用尤其重要，因为大量工作是 API、数据库、MCP、HTTP 和流式响应等 I/O。

## 先区分三个概念

### Concurrency
多个任务交替推进。

### Parallelism
多个任务真正同时执行。

### Async
一种非常适合大量 I/O 的并发模型。

## asyncio
- 官方：https://docs.python.org/3/library/asyncio.html
- Task：https://docs.python.org/3/library/asyncio-task.html

核心概念：

```text
async def
↓
Coroutine
↓
await
↓
Task
↓
Event Loop
```

重点掌握：
- async / await
- create_task
- gather
- TaskGroup
- timeout
- cancellation
- queue
- semaphore

## asyncio 适合什么

适合：
- HTTP API
- LLM API
- Database I/O
- WebSocket
- Streaming
- 多 Tool 调用

不适合：
- 大量纯 CPU 运算

## Thread
- 官方：https://docs.python.org/3/library/concurrent.futures.html

ThreadPoolExecutor 适合：
- 第三方同步 SDK
- 阻塞型 I/O
- 不能改造成 async 的旧代码

## Process
- multiprocessing：https://docs.python.org/3/library/multiprocessing.html
- ProcessPoolExecutor：https://docs.python.org/3/library/concurrent.futures.html

适合：
- CPU-heavy
- 数据处理
- 图片处理
- 大量计算

## 性能分析

https://docs.python.org/3/library/profile.html

### timeit

## Agent 项目的典型模式

```text
User Request
   ↓
同时请求多个 Tool
   ↓
asyncio TaskGroup
   ↓
等待结果
   ↓
聚合
   ↓
LLM
```

## 我的结论

先记住：

- I/O-heavy → asyncio
- 阻塞型 I/O → Thread
- CPU-heavy → Process
- 性能问题 → 先测量，不凭感觉优化
